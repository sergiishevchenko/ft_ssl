# Whirlpool на примере `abc`

Документ проводит строку `abc` через весь код `ft_ssl` до готового хеша. Каждое число ниже посчитано тем же алгоритмом, что в `srcs/whirlpool/whirlpool.c`, и сверено с выводом программы и официальным тестовым вектором Whirlpool для `abc`. Таблицы `g_whirlpool_c0` и `g_whirlpool_rc` проверены пересчётом из S-box и матрицы MDS.

Общая схема программы (разбор флагов, форматы вывода) описана в [how-it-works.md](how-it-works.md). MD5 и SHA-256 на том же примере — в [md5.md](md5.md) и [sha256.md](sha256.md).

## Пример

```text
$ ./ft_ssl whirlpool -s "abc"
WHIRLPOOL ("abc") = 4e2448a4c6f486bb16b6562c73b4020bf3043e3a731bce721ae1b303d97e6d4c7181eebdb6c57e277d0e34957114cbd6c797fc9d95d8b582d225292076d4eef5

$ printf 'abc' | openssl dgst -whirlpool -provider legacy -provider default
WHIRLPOOL(stdin)= 4e2448a4c6f486bb16b6562c73b4020bf3043e3a731bce721ae1b303d97e6d4c7181eebdb6c57e277d0e34957114cbd6c797fc9d95d8b582d225292076d4eef5
```

Сообщение — три байта `61 62 63`, 24 бита. Дайджест — 64 байта, 128 hex-символов.

## Чем Whirlpool отличается от MD5 и SHA-256

MD5 и SHA-256 — специально придуманные функции сжатия на 32-битных сложениях и поворотах. Whirlpool устроен иначе: внутри него блочный шифр `W`, родственник AES. Хеш получается из шифра по схеме Miyaguchi–Preneel:

```text
H_новое = W(ключ = H_старое, текст = блок) ^ H_старое ^ блок
```

Сложений нет совсем. Есть только подстановка байт по таблице, умножение в поле \(GF(2^8)\) и XOR.

| | MD5 | SHA-256 | Whirlpool |
|---|---|---|---|
| блок | 64 байта | 64 байта | 64 байта |
| состояние | 4 × 32 бита | 8 × 32 бита | 8 × 64 бита |
| выход | 128 бит | 256 бит | 512 бит |
| раундов на блок | 64 | 64 | 10 (и ещё 10 для ключа) |
| операции | `+`, повороты, `& \| ^ ~` | `+`, повороты, сдвиги, `& ^ ~` | S-box, умножение в \(GF(2^8)\), `^` |
| начальное состояние | 4 константы | 8 констант | нули |
| поле длины | 8 байт LE | 8 байт BE | 32 байта BE |
| финал блока | `state += …` | `state += …` | `state ^= шифр ^ блок` |

## Краткая карта алгоритма

```text
"abc" (3 байта)
   │
   ▼  whirlpool_init      весь контекст = 0, state[0…7] = 0
   │
   ▼  whirlpool_update    buffer = 61 62 63, buflen = 3, count = 3
   │
   ▼  whirlpool_final     buffer: 61 62 63 80 00 … 00 | 24 нуля | 00 00 00 00 00 00 00 18
   │                                    байты 0–31      32–55          56–63
   ▼  whirlpool_transform
   │     blk = 8 слов big-endian
   │     k = state = 0             ключ
   │     s = blk ^ k               текст шифра
   │     10 раз:
   │        k = ρ(k) ^ rc[r]       следующий ключ раунда
   │        s = ρ(s) ^ k           раунд шифра
   │     state ^= s ^ blk
   ▼  выгрузка            8 слов → 64 байта, старший байт первым
   │
   ▼  digest_to_hex       64 байта → 128 символов
```

## 1. Как программа доходит до Whirlpool

`find_hash("whirlpool")` возвращает третью запись `g_hashes`:

```c
{"WHIRLPOOL", "whirlpool", 64, sizeof(t_whirlpool_ctx),
	whirlpool_init, whirlpool_update, whirlpool_final},
```

`64` — размер дайджеста в байтах. В `process_string` буферы `digest[64]` и `hex[129]` рассчитаны как раз на Whirlpool, самый длинный из трёх.

Дальше тот же путь: `execute_command` → `parse_flags` → `process_string("abc")` → `hash_data` → `whirlpool_init`, `whirlpool_update`, `whirlpool_final` → `digest_to_hex(digest, 64, hex)` → `print_hash_result`.

## 2. Контекст и `whirlpool_init`

```c
typedef struct s_whirlpool_ctx
{
	uint64_t	state[8];
	uint64_t	count;
	uint8_t		buffer[64];
	uint32_t	buflen;
}	t_whirlpool_ctx;
```

`whirlpool_init` делает один `ft_memset(c, 0, sizeof(t_whirlpool_ctx))`. Начальное состояние — 512 нулевых бит. Отдельные константы не нужны: вся «случайность» сидит в S-box.

## 3. `whirlpool_update(ctx, "abc", 3)`

Тот же цикл, что у MD5 и SHA-256: три байта в `buffer[0…2]`, `buflen = 3`, `count = 3`. Сжатия нет.

## 4. `whirlpool_final`: паддинг

Стандарт Whirlpool отводит под длину 256 бит (32 байта). Значит, `0x80` и нули должны закончиться на байте 31, а не 55.

```c
bits = c->count * 8;
c->buffer[c->buflen++] = 0x80;
if (c->buflen > 32)
{
	while (c->buflen < 64)
		c->buffer[c->buflen++] = 0x00;
	whirlpool_transform(c, c->buffer);
	c->buflen = 0;
}
while (c->buflen < 32)
	c->buffer[c->buflen++] = 0x00;
ft_memset(c->buffer + 32, 0, 24);
```

Для `abc`:

1. `bits = 24 = 0x18`.
2. `buffer[3] = 0x80`, `buflen = 4`.
3. `4 > 32` ложно, лишнего блока нет.
4. Нули в `buffer[4…31]`, `buflen = 32`.
5. `ft_memset` обнуляет `buffer[32…55]`. Это старшие 24 байта 256-битной длины. `count` у нас 64-битный, поэтому они всегда нулевые.
6. Цикл как в SHA-256 пишет 64-битную длину старшим байтом вперёд в `buffer[56…63]`: семь нулей и `18`.

| смещение | байты |
|---|---|
|  0–15 | `61 62 63 80 00 00 00 00 00 00 00 00 00 00 00 00` |
| 16–31 | `00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00` |
| 32–47 | `00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00` |
| 48–63 | `00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 18` |

Для `abc` байты блока совпадают с блоком SHA-256: там тоже `80`, нули и длина big-endian в конце. Разница проявится только на хвосте от 32 байт, см. раздел 10.

## 5. Состояние как матрица 8×8

Whirlpool думает о 64 байтах как о матрице 8 × 8 байт. В коде строка матрицы — одно слово `uint64_t`, столбец — позиция байта в слове, считая от старшего:

```text
            столбец t:   0    1    2    3    4    5    6    7
state[0] = строка 0:    61   62   63   80   00   00   00   00
state[1] = строка 1:    00   00   00   00   00   00   00   00
   …
state[7] = строка 7:    00   00   00   00   00   00   00   18
```

Байт `t` слова `w` достаётся так: `(uint8_t)(w >> (56 - t * 8))`. При `t = 0` это сдвиг на 56, старший байт.

`wp_load_block` собирает слова big-endian:

| i | байты блока | blk[i] |
|---|---|---|
| 0 | `61 62 63 80 00 00 00 00` | `6162638000000000` |
| 1 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 2 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 3 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 4 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 5 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 6 | `00 00 00 00 00 00 00 00` | `0000000000000000` |
| 7 | `00 00 00 00 00 00 00 18` | `0000000000000018` |

## 6. Раунд `ρ`: что делает `wp_round`

### 6.1. Четыре операции из стандарта

Раунд шифра `W` по стандарту — композиция четырёх операций над матрицей:

| операция | обозначение | что делает |
|---|---|---|
| SubBytes | γ | каждый байт заменяется по S-box: `x → S[x]` |
| ShiftColumns | π | столбец `t` циклически сдвигается вниз на `t` позиций |
| MixRows | θ | каждая строка умножается на матрицу MDS 8 × 8 над \(GF(2^8)\) |
| AddRoundKey | σ | XOR с ключом раунда |

Код не делает их по отдельности. `wp_round` за один проход считает одну строку результата γ, π и θ. σ выполняется снаружи: `^ k[i]` для шифра и `^ rc[r]` для ключа.

### 6.2. Код

```c
static uint64_t	wp_round(const uint64_t *state, int row)
{
	uint64_t	result;
	uint64_t	c;
	int			t;
	uint8_t		idx;

	result = 0;
	t = 0;
	while (t < 8)
	{
		idx = (uint8_t)(state[(row - t + 8) % 8] >> (56 - t * 8));
		c = g_whirlpool_c0[idx];
		if (t > 0)
			c = (c >> (t * 8)) | (c << (64 - t * 8));
		result ^= c;
		t++;
	}
	return (result);
}
```

Разбор по частям:

- `state[(row - t + 8) % 8]` и байт `t` — это π. После сдвига столбца `t` вниз на `t` в строке `row` оказывается элемент, который раньше стоял в строке `row - t`. `+ 8` нужно, чтобы остаток не стал отрицательным.
- `g_whirlpool_c0[idx]` — это γ и θ сразу. Таблица уже содержит `S[idx]`, умноженный на все восемь коэффициентов первой строки MDS.
- Поворот вправо на `t` байт подставляет коэффициенты для позиции `t`. Матрица MDS циркулянтная: каждая следующая строка — предыдущая, сдвинутая на один вправо. Поэтому одной таблицы хватает, а не восьми (`C0…C7` в эталонной реализации).
- XOR восьми слагаемых — это сумма в умножении строки на матрицу. В \(GF(2^8)\) сложение и есть XOR.

### 6.3. Откуда берётся `C0`

Матрица MDS Whirlpool — `circ(1, 1, 4, 1, 8, 5, 2, 9)`. Умножение идёт в поле \(GF(2^8)\) по модулю многочлена \(x^8 + x^4 + x^3 + x^2 + 1\) (`0x11D`).

Как умножить байт на 2: сдвинуть влево на 1; если вылез бит 8, сделать XOR с `0x11D`. Умножение на 4 и 8 — это два и три таких удвоения. На 5 — `·4 ^ ·1`, на 9 — `·8 ^ ·1`.

`C0[x]` — 8 байт подряд: `S[x]·1, S[x]·1, S[x]·4, S[x]·1, S[x]·8, S[x]·5, S[x]·2, S[x]·9`. Старший байт `C0[x]` равен `S[x]`, поэтому S-box можно прочитать прямо из таблицы. Первые 16 значений S-box:

```text
S[00…0f] = 18 23 c6 e8 87 b8 01 4f 36 a6 d2 f5 79 6f 91 52
```

Пример, который понадобится ниже: `x = 0x61` (буква `a`), `S[0x61] = 0x0f`.

| j | множитель c[j] | S[61] · c[j] в GF(2^8) |
|---|---|---|
| 0 | 1 | `0f` |
| 1 | 1 | `0f` |
| 2 | 4 | `3c` |
| 3 | 1 | `0f` |
| 4 | 8 | `78` |
| 5 | 5 | `33` |
| 6 | 2 | `1e` |
| 7 | 9 | `77` |

Итого `C0[0x61] = 0f0f3c0f78331e77`. Значение в `whirlpool_tables.c` совпадает. Числа маленькие, поэтому редукция по `0x11D` здесь не понадобилась.

### 6.4. Константы раунда

```c
const uint64_t	g_whirlpool_rc[10] = {
	0x1823c6e887b8014fULL,
	0x36a6d2f5796f9152ULL,
```

`rc[r]` — восемь подряд идущих байт S-box: `S[8r], S[8r+1], …, S[8r+7]`. `rc[0] = 18 23 c6 e8 87 b8 01 4f` — первые восемь байт из строки выше. Константа ксорится только в строку 0 ключа (`nk[0] ^= …`). Остальные строки константы нулевые.

## 7. `whirlpool_transform` по шагам

### 7.1. Подготовка

```c
wp_load_block(blk, block);
i = -1;
while (++i < 8)
{
	k[i] = ctx->state[i];
	s[i] = blk[i] ^ k[i];
}
```

Ключ `k` — текущее состояние, для первого блока это нули. Текст шифра `s = blk ^ k = blk`. Это первое применение σ: стандарт ксорит текст с нулевым ключом раунда до начала раундов.

### 7.2. Цикл раундов

```c
while (r < 10)
{
	i = -1;
	while (++i < 8)
		nk[i] = wp_round(k, i);
	nk[0] ^= g_whirlpool_rc[r];
	k = nk;
	i = -1;
	while (++i < 8)
		ns[i] = wp_round(s, i) ^ k[i];
	s = ns;
	r++;
}
```

Два параллельных процесса:

- **ключ**: `k_r = ρ(k_{r-1}) ^ rc[r]`. Ключ шифра — это предыдущий хеш, и он сам прогоняется через тот же раунд с константами вместо ключа.
- **текст**: `s_r = ρ(s_{r-1}) ^ k_r`. Новый ключ раунда считается раньше, чем используется.

Временные массивы `nk` и `ns` нужны потому, что `wp_round` для строки 1 читает строку 0 старого значения. Перезапись на месте испортила бы следующие строки.

### 7.3. Раунд 1, ключ, строка 0

`k` целиком нулевой, поэтому все восемь байт — `00`, и все восемь раз берётся `C0[00]`:

| t | слово k[(0−t) mod 8] | байт t | C0[байт] | сдвиг вправо на t байт |
|---|---|---|---|---|
| 0 | k[0] = `0000000000000000` | `00` | `18186018c07830d8` | `18186018c07830d8` |
| 1 | k[7] = `0000000000000000` | `00` | `18186018c07830d8` | `d818186018c07830` |
| 2 | k[6] = `0000000000000000` | `00` | `18186018c07830d8` | `30d818186018c078` |
| 3 | k[5] = `0000000000000000` | `00` | `18186018c07830d8` | `7830d818186018c0` |
| 4 | k[4] = `0000000000000000` | `00` | `18186018c07830d8` | `c07830d818186018` |
| 5 | k[3] = `0000000000000000` | `00` | `18186018c07830d8` | `18c07830d8181860` |
| 6 | k[2] = `0000000000000000` | `00` | `18186018c07830d8` | `6018c07830d81818` |
| 7 | k[1] = `0000000000000000` | `00` | `18186018c07830d8` | `186018c07830d818` |

```text
XOR восьми значений = 2828282828282828
^ rc[0]             = 1823c6e887b8014f
k[0] после раунда 1 = 300beec0af902967
```

Для нулевого ключа `wp_round` возвращает `2828282828282828` на любой строке. Поэтому после раунда 1 строки ключа 1–7 одинаковые, а строку 0 отличает только `rc[0]`. К следующему раунду симметрия разрушается.

### 7.4. Раунд 1, текст, строка 0

`s` перед раундом — это `blk`. В строке 0 результата участвует байт 0 из `s[0]`, байт 1 из `s[7]`, байт 2 из `s[6]` и так далее по диагонали:

### 7.5. Раунд 1, текст, строка 3

Здесь видно, как байт `80` из `s[0]` попадает в строку 3:

| t | слово s[(3−t) mod 8] | байт t | C0[байт] | сдвиг вправо на t байт |
|---|---|---|---|---|
| 0 | s[3] = `0000000000000000` | `00` | `18186018c07830d8` | `18186018c07830d8` |
| 1 | s[2] = `0000000000000000` | `00` | `18186018c07830d8` | `d818186018c07830` |
| 2 | s[1] = `0000000000000000` | `00` | `18186018c07830d8` | `30d818186018c078` |
| 3 | s[0] = `6162638000000000` | `80` | `97976697ccf1335b` | `f1335b97976697cc` |
| 4 | s[7] = `0000000000000018` | `00` | `18186018c07830d8` | `c07830d818186018` |
| 5 | s[6] = `0000000000000000` | `00` | `18186018c07830d8` | `18c07830d8181860` |

```text
XOR восьми значений = a12baba7a72ea724
^ k[3] раунда 1     = 2828282828282828
s[3] после раунда 1 = 8903838f8f068f0c
```

Байт длины `18` стоит в столбце 7 строки 7. Столбец 7 сдвигается вниз на 7 позиций, а это то же самое, что на одну вверх. Поэтому `18` участвует в строке 6: при `row = 6, t = 7` код читает `s[(6 - 7 + 8) % 8] = s[7]`.

В таблице ниже после раунда 1 строки `s[4]`, `s[5]` и `s[7]` нулевые. В них по диагонали попали только нулевые байты, `wp_round` дал для них `2828282828282828`, и ровно это же значение лежит в `k[4]`, `k[5]`, `k[7]`. XOR одинаковых чисел даёт ноль. Ненулевые строки 1, 2, 3 получили байты `62`, `63`, `80`, строка 6 — байт длины `18`.

После одного раунда каждый байт входа влияет на одну строку целиком (через θ). После двух — на всю матрицу. Десяти раундов хватает с большим запасом.

### 7.7. Финал блока: Miyaguchi–Preneel

```c
ctx->state[i] ^= s[i] ^ blk[i];
```

`^=` даёт три слагаемых: старое состояние, выход шифра и исходный блок. Для первого блока старое состояние нулевое.

|---|---|---|---|
| 0 | `2f462b24c6f486bb` | `6162638000000000` | `4e2448a4c6f486bb` |
| 1 | `16b6562c73b4020b` | `0000000000000000` | `16b6562c73b4020b` |
| 2 | `f3043e3a731bce72` | `0000000000000000` | `f3043e3a731bce72` |
| 3 | `1ae1b303d97e6d4c` | `0000000000000000` | `1ae1b303d97e6d4c` |
| 4 | `7181eebdb6c57e27` | `0000000000000000` | `7181eebdb6c57e27` |

Зачем XOR с блоком и со старым состоянием: без них функция была бы обратимой. Зная ключ (прошлый хеш) и выход, шифр можно расшифровать и получить блок. С обратной связью этого сделать нельзя.

## 8. Выгрузка и печать


## 10. Когда паддинг занимает лишний блок

Лишний блок нужен, если после `0x80` занято больше 32 байт. Хвост — `count mod 64`.

| хвост | `buflen` после `0x80` | блоков в `final` |
|---|---|---|
| 0–31 | 1–32 | 1 |
| 32–63 | 33–64 | 2 |

Граница в два раза раньше, чем у MD5 и SHA-256 (там 56), из-за 32-байтного поля длины. Пример: сообщение длиной 40 байт в SHA-256 закроется одним блоком, а в Whirlpool — двумя.

Как работает ветка для хвоста 40: `buflen` после `0x80` равен 41, условие `> 32` истинно. Нули до 64, `whirlpool_transform`, `buflen = 0`. Затем 32 нуля, 24 нуля из `ft_memset`, длина в 56–63, второй `whirlpool_transform`.

Пустое сообщение: блок `80`, 55 нулей, восемь нулей длины. Хеш:

```text
19fa61d75522a4669b44e39c1d2e1726c530232130d407f89afee0964997f7a73e83be698b288febcf88e3e03c4f0757ea8964e59b63d93708b138cc42a66eb3
```

## 11. Как проверить самому

```bash
./ft_ssl whirlpool -s "abc"
./ft_ssl whirlpool -s ""
printf 'abc' | openssl dgst -whirlpool -provider legacy -provider default
```

В OpenSSL 3 и новее Whirlpool лежит в legacy-провайдере. Без `-provider legacy -provider default` команда падает с `unsupported`. Эталонные значения есть в описании алгоритма от авторов (Barreto, Rijmen) и в ISO/IEC 10118-3.

## 12. Стойкость

Практических атак на полный Whirlpool нет. Лучшие известные атаки находят коллизии только для сокращённого числа раундов. На практике он используется редко: SHA-2 и SHA-3 стали стандартом, а Whirlpool в типичных программных реализациях медленнее SHA-256.
